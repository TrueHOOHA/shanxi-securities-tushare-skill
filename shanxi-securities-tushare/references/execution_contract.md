# Execution Contract（唯一详细规范）

> 适用范围：`shanxi-securities-tushare` skill 的所有执行流程。  
> 本文档是“查表优先、参数确认、输出结构、错误处理”的唯一详细版本；`SKILL.md`、`README.md`、`intent_taxonomy.md`、`workflow_templates.md` 仅保留简版约束并指向本文。

## 1. 查表优先（强制）

每次调用 API 前，必须按以下顺序执行：
1. 查 `references/API接口对应表.md`，确定 `pro.api_name` 与对应文档。
2. 打开对应 `references/XXX.md`，确认入参、字段、限额、适用场景。
3. 再组织调用参数与执行代码。

禁止行为：
- 凭记忆直接写接口名。
- 未核对文档就猜测 `fields` 或参数含义。

## 2. 参数确认（强制）

执行前必须完成参数规范化与冲突裁决：
- 日期统一 `YYYYMMDD`。
- 校验 `start_date <= end_date`。
- 用户输入未来日期时，自动裁剪到最近可用日期并提示。
- 裸代码（如 `000001`）需按规则补全；无法唯一补全时做最小澄清。
- 冲突参数（如 `trade_date` 与 `start_date/end_date` 同时给）必须先裁决，再调用。
- `fields` 仅使用文档已确认字段；用户要求不存在字段时，明确告知不可用。

## 3. 输出结构（默认）

除非用户明确要求原始表，默认按以下结构交付：
1. 一句话结论
2. 数据范围与口径
3. 关键指标/关键表格
4. 异常点/风险点/解释限制
5. 本地输出文件路径（如有）

交付形态建议：
- 小结果：Markdown 摘要 + 短表。
- 中等数据：CSV。
- 大规模/复用：Parquet + 脚本。

输出元信息建议：接口名、请求参数、拉取时间、数据行数、字段列表、失败分段。

## 4. 错误处理（分层）

### 4.1 可重试错误
- 网络抖动、超时、429（限流）可有限重试并节流。

### 4.2 不可盲重试错误
- 参数错误、权限不足、字段不存在、接口不支持。
- 这类错误需直接暴露原因并给修复建议。

### 4.3 分段拉取与部分成功
- 长区间按年/季度或按标的分批拉取。
- 合并后去重、按主键排序、记录失败分段。
- 若部分成功，必须明确说明成功/失败范围。

## 5. 术语规范（统一写法）

为减少语义分叉，统一使用以下术语：
- 使用“**查表优先**”（不再使用“文档先行”等同义写法）。
- “参数确认”指调用前的规范化、校验与冲突裁决。
- “输出结构”指默认 5 段式交付格式。
- “错误处理”指重试策略 + 非重试错误暴露 + 分段失败披露。
